# Cambio y parche de emergencia

**Código:** SEC-CHG-007 · **Versión:** 2.4

Un parche de emergencia requiere evidencia de riesgo urgente, propietario técnico, evaluación de dependencias, plan de validación y rollback. Antes: snapshot o backup verificado, capacidad y comunicación. Durante: lote pequeño, monitoreo y criterios de abortar. Después: prueba funcional, verificación de versión, escaneo y observación.

Si no puede parchearse, documente mitigaciones temporales como aislamiento, deshabilitar función, WAF o restricción de acceso. Toda mitigación tiene fecha de caducidad y responsable. No confunda instalación exitosa con remediación verificada.
